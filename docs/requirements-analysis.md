# 推荐系统需求分析

## 1. 项目背景

本项目为基于协同过滤的课程/毕设推荐系统，目标是在已有用户-物品评分数据基础上，为指定用户生成高质量推荐结果，并提供离线评估能力，支撑算法对比与论文实验分析。

当前系统已具备：

- 用户协同过滤（User-Based CF）
- 物品协同过滤（Item-Based CF）
- 混合推荐（Hybrid）与冷启动兜底
- 离线评估接口（Precision@K / Recall@K / NDCG@K / Coverage）
- 评估结果导出（CSV / HTML / TEX / Summary）
- 合成数据生成脚本（用于扩充训练与验证数据）

## 2. 需求目标

### 2.1 业务目标

- 提供可解释、可复现、可对比的推荐能力
- 提升 Top-N 结果质量，重点提升 Precision@1
- 为论文提供完整实验链路：数据准备、算法评估、结果导出

### 2.2 技术目标

- 构建可扩展的推荐算法架构，支持策略切换和组合
- 提供稳定接口与统一错误响应，便于前后端联调
- 支持本地快速部署、数据初始化与自动化验证

## 3. 干系人与使用场景

### 3.1 干系人

- 学生开发者：实现算法、完成论文实验
- 指导老师：关注指标、实验设计和可复现性
- 答辩评审：关注系统完整性、性能与可解释性

### 3.2 核心场景

- 场景 A：输入用户 ID，按指定算法返回推荐列表
- 场景 B：离线评估不同算法效果，比较指标
- 场景 C：批量生成实验数据，重复训练与评测
- 场景 D：导出可直接用于论文的图表与表格素材

## 4. 功能需求

### FR-01 推荐查询

- 输入：`userId`、`n`、`algo`
- 输出：推荐物品列表（itemId、name、category、score）
- 算法支持：`user` / `item` / `hybrid`
- 约束：`n` 自动限制在 1~100

### FR-02 算法策略切换

- 支持用户协同过滤、物品协同过滤、混合策略
- 混合策略应融合多路候选并进行排序
- 对无足够候选时支持热门兜底

### FR-03 离线评估

- 支持按参数执行离线评测：`k`、`testRatio`、`relevance`
- 输出指标：Precision@K、Recall@K、NDCG@K、Coverage、可评估用户数
- 同时输出 user/item/hybrid 三种算法结果

### FR-04 实验结果导出

- 提供 CSV 导出接口
- 提供脚本生成 HTML 可视化、LaTeX 表格、摘要结论
- 支持多组 K 值批量对比

### FR-05 数据准备

- 支持 schema/data 自动初始化
- 支持合成数据生成并导出 SQL
- 支持通过 MySQL 导入并覆盖指定区间数据

### FR-06 错误处理

- 参数非法、算法类型非法等场景返回统一错误结构
- 状态码与错误信息需准确，便于调试与自动测试

## 5. 非功能需求

### NFR-01 性能

- 推荐接口单次请求响应时间目标：常规数据集下 < 500ms
- 离线评估在中等规模数据集可在可接受时间内完成
- 合成数据脚本应有进度反馈，避免“无响应”感知

### NFR-02 可用性

- 脚本在 Windows PowerShell 环境可直接运行
- 提供 `.cmd` 包装入口，降低执行策略与路径问题

### NFR-03 可维护性

- 算法实现解耦，便于后续新增模型
- 评估指标统一由离线评估服务输出
- 文档化运行方式、排错方式、实验流程

### NFR-04 可复现性

- 合成数据支持随机种子，保证实验可重复
- 评估参数可配置，输出文件结构固定

### NFR-05 安全性

- 不在代码仓库中硬编码生产环境敏感信息
- 数据操作以本地实验库为主，避免误删业务数据

## 6. 数据需求分析

### 6.1 数据实体

- `users`：用户信息
- `items`：物品信息
- `ratings`：用户对物品评分（核心训练数据）

### 6.2 数据质量要求

- 评分范围需满足业务约束（0~5）
- 每个用户与每个物品需有最低交互量，避免稀疏过度
- 去重规则：同一用户对同一物品仅保留一条评分

### 6.3 数据规模目标（实验建议）

- 基础验证：200 用户 / 120 物品
- 论文实验：1200 用户 / 600 物品及以上

## 7. 接口需求分析

### 7.1 推荐接口

- `GET /api/recommendations/{userId}?n=5&algo=user|item|hybrid`

### 7.2 评估接口

- `GET /api/evaluations/offline?k=10&testRatio=0.2&relevance=4.0`
- `GET /api/evaluations/offline/csv?k=10&testRatio=0.2&relevance=4.0`

### 7.3 脚本接口

- `scripts/run-generate-synthetic.cmd`
- `scripts/run-export-eval.cmd`

## 8. 约束条件

- 开发环境：Windows + Java 17 + Maven + MySQL 8
- 项目技术栈：Spring Boot + JPA + MockMvc 测试
- 算法当前以记忆型协同过滤为主，暂不引入深度学习模型

## 9. 验收标准

### 9.1 功能验收

- 推荐接口可按三种算法返回结果
- 冷启动场景不返回空列表
- 离线评估接口返回完整指标
- 脚本可生成评估产物和合成数据 SQL

### 9.2 指标验收

- 在同一测试集上可完成 user/item/hybrid 的对比
- 可输出 Precision@1 作为核心优化指标
- 评估过程和结果可重复

### 9.3 工程验收

- `mvn test` 通过
- `mvn -DskipTests package` 通过
- 文档可指导从零完成“生成数据->导入->评估->导出”

## 10. 后续迭代建议

- 增加自动调参（重点针对 Precision@1）
- 增加时间衰减与新颖性/多样性指标
- 引入在线日志埋点，支持轻量 A/B 评估
- 提供论文段落模板自动生成，缩短实验写作周期
